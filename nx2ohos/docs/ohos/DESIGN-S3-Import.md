# S3 导入流程：详细设计

> 阶段：**设计评审**。定稿后实现。
> 依赖：S2 库界面（`12afabc`）、P2.1 导入引擎（PackImport.ets，已设备验证）
> 上游：[DESIGN-GameLibrary.md](DESIGN-GameLibrary.md) §5.5

---

## 1. 问题

导入是用户花时间最长的操作（14.75 GB 首次约 13 分钟，正常态是"已有数据、stamp 匹配、零导入"）。当前的导入逻辑在 Index.ets 里工作正常但**没有产品级反馈**：

| 缺失 | 后果 |
|---|---|
| 没有剩余时间 | 百分比对 13 分钟没有意义 |
| 没有明确"可离开" | 用户以为必须盯着屏幕 |
| 错误码直接暴露 | `code 2300018` 不可理解 |
| 导入完成不落库界面 | 用户不知道成功了 |
| 没有"重新导入已存在的游戏"的确认 | 误导入覆盖 14.75 GB 数据无提示 |

## 2. 导入的三个真实场景

| 场景 | 触发 | 期望 |
|---|---|---|
| **全新游戏** | 库里没有该 title | 直接导入，完成后出现在库里 |
| **同版本重装** | stamp 匹配 | **秒过**（stamp 命中，零拷贝），提示"已是最新" |
| **数据更新** | stamp 不匹配，title 相同 | **确认后**清旧导新，明确说会替换 |

## 4. 组件

### 4.1 ImportBanner（顶栏下细进度条）

- 高 **4dp**，`accent` 渐变填充，位置在 TopBar 底部
- **任何导入进行中**都显示（包括 picker 和 loopback 两条路径）
- 不可交互（不抢焦点）；下方文字 "正在导入 {游戏名}" `font/caption` 12dp
- 完成后 400ms 淡出

### 4.2 ImportPanel（详情面板，底部抽屉式）

| 元素 | 规格 |
|---|---|
| 容器 | `bg/elevated`，`radius/lg` 上圆角，`z/sheet` |
| 游戏名 | `font/title`，`text/primary` |
| 进度条 | 高 8dp，`accent` 渐变，200ms 缓动 |
| 进度数字 | `6.3 GB / 14.7 GB`（已下载+已解包合并显示） |
| **剩余时间** | `约 7 分钟`（滑动平均速度 × 剩余字节，>60s 显示分钟，<60s 显示秒）|
| 当前文件 | `font/caption`，单行省略（"正在写入 RomFS/Model/…"）|
| 说明文字 | "可以离开此页面，导入会在后台继续。中断后重新打开会从断点继续。" |
| 后台继续 | Button secondary，关闭面板但导入继续 |
| 取消导入 | Button danger，二次确认 |

### 4.3 剩余时间估算

```typescript
// 滑动窗口：最近 10 秒的吞吐
const window: {t: number, bytes: number}[] = [];  // 每 2 秒采样一次
rate = (最新.bytes - 窗口头.bytes) / (最新.t - 窗口头.t)   // bytes/ms
remaining = (totalBytes - doneBytes) / rate
// 显示：<60s → "约 30 秒"；<3600s → "约 7 分钟"；否则 → "约 1.2 小时"
// 前 15 秒不显示（样本不足，数字会跳）
```

### 4.4 取消的二次确认

```
┌────────────────────────────────────┐
│  取消导入？                         │
│                                    │
│  已下载 6.3 GB 将保留，              │
│  下次导入从断点继续。                │
│                                    │
│  [继续导入]     [取消导入]           │
└────────────────────────────────────┘
```

**关键差异**：与删除不同，取消导入**不丢数据**（.part 保留，续传），所以文案强调"将保留"而不是恐吓。危险按钮仍然红色，默认焦点在"继续导入"。

### 4.5 完成反馈

- 进度条满 → banner 淡出 → **新游戏卡片以 1.08 缩放 + 主题色光晕出现**（利用 S2 的焦点视觉）→ 焦点自动落在新卡片
- Toast："已导入 {游戏名}"
- 库列表刷新（`refreshLibrary`），新游戏排最前（stamp 倒序）

### 4.6 错误文案（复用设计文档 §6）

| 技术 | 显示 |
|---|---|
| `2300023`（磁盘满/写失败）| 存储空间不足，需要 14.7 GB 空间 |
| `2300028`（超时）| 传输超时，下次会从断点继续 |
| `magic != NXPK` | 这不是游戏包，请选择 .nxpk 文件 |
| stamp 匹配 | **秒过** + Toast "该游戏已是最新版本" |

### 4.7 数据更新确认

导入已存在且 stamp 不同的包：

```
┌────────────────────────────────────┐
│  更新 游戏数据？                     │
│                                    │
│  塞尔达传说 已安装。                 │
│  新数据包将替换 14.7 GB 旧数据。      │
│  存档不受影响。                     │
│                                    │
│  [取消]        [替换]               │
└────────────────────────────────────┘
```

## 5. 状态机

```
           picker 选文件 / loopback 检测
                      ↓
              读 header（NXPK 魔数）
                      ↓ 失败 → Toast "这不是游戏包"
              stamp 比对
                      ↓
        ┌── 匹配 → Toast "已是最新" → 结束（零拷贝）
        │
        └── 不匹配：
            ├── title 已在库 → ConfirmDialog "替换？" → 取消则结束
            │
            └── 继续：
                  importing = true, banner 出现
                  ↓
              下载/解包（复用 PackImport + stageData）
                  ↓ 每次进度回调
              更新 banner/panel；采样速率算剩余时间
                  ↓
        ┌── 完成 → writeStamp + writeMeta + 刷新库 + 焦点落新卡片 + Toast
        ├── 取消 → .part 保留 → banner 消失 → Toast "已取消，下次从断点继续"
        └── 失败 → banner 消失 → Toast 错误文案
```

## 6. 实现清单

| # | 文件 | 内容 |
|---|---|---|
| 1 | `components/ImportBanner.ets` | 顶栏下 4dp 细进度条 |
| 2 | `components/ImportPanel.ets` | 详情面板（进度/剩余时间/当前文件/两个按钮）|
| 3 | `components/ConfirmDialog.ets` | 通用确认对话框（取消导入/替换数据两用）|

| 5 | `pages/GameLibrary.ets` | `importPackStatus()`：全局导入状态单例（下载+解包合并进度）|

### 验收标准

1. 选 .nxpk → banner 出现 → 进度条推进 → 完成后新卡片出现 + Toast
2. 详情面板显示**剩余时间**（15 秒后稳定，不跳变）
3. 取消 → 二次确认 → .part 保留 → 重启续传
4. 同包重导 → stamp 命中 → 秒过 + "已是最新"
5. 数据更新 → 确认框（提到存档安全）→ 替换成功
6. 磁盘满 → 人话错误提示
7. 导入期间**可继续操作库**（非模态）
8. loopback 导入走同一套反馈（开发路径同产品路径）
