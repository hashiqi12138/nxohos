# S4 游戏库：远程源、下载、启动、管理

> 阶段：**设计**。定稿后写代码。
> 前置：S1 令牌（`theme/Tokens.ets`）· S2 库页（`LibraryPage.ets`）· S3 导入（`ImportPanel.ets`）
> 现状：库页已是入口（`EntryAbility` 加载 `pages/LibraryPage`），但只能导入本地 `.nxpk`。

---

## 1. 这一屏现在缺什么

S2 做完了"看到 + 启动"，但**游戏从哪来**只有一条路：文件选择器挑一个 `.nxpk`。
真实使用里，游戏在电脑上，用户在沙发上。S4 补的是这条路。

三个新问题，按用户会问的顺序：

1. **"我电脑上那些游戏，怎么弄到平板上？"** → 远程源
2. **"下载的时候我在哪、能不能走开？"** → 下载可见、可离开
3. **"不玩了想删掉，或者删了重下"** → 管理

---

## 2. 核心设计决策

### 决策一：远程包不混进主网格

**主网格 = 我已拥有的游戏。** 远程包是"可以拥有的"，两者性质不同：
主网格的卡片点了就玩，远程卡片点了要下载。混在一起，用户分不清哪些已经在自己机器上。

**做法**：主网格下方一个独立的「可下载」区，视觉上收一档（小行、无封面、卡片底色 `Bg.card` 而非封面图）。

```
┌──────────────────────────────────────────────────────────────────┐
│  NXOHOS                                    [⚙]  [＋ 添加游戏]     │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐                      │
│   │    Z     │  │    ＋    │  │          │   ← 已安装（封面网格） │
│   │          │  │  添加    │  │          │                      │
│   ├──────────┤  ├──────────┤  └──────────┘                      │
│   │塞尔达     │  │          │                                   │
│   │14.7 GB   │  │          │                                   │
│   │● 可运行   │  │          │                                   │
│   └──────────┘  └──────────┘                                   │
│                                                                  │
│   ───────────────────────────────────────────────────────────    │
│   可下载                                        [刷新]  192.168.2.2 │ ← 区标题
│   ┌──────────────────────────────────────────────────────────┐   │
│   │  Celeste.nxpk                          1.17 GB   [下载]  │   │
│   │  01002B30028F6000                                        │   │
│   ├──────────────────────────────────────────────────────────┤   │
│   │  Mario Kart 8.nxpk                     6.10 GB   [下载]  │   │
│   │  0100152000022000                                        │   │
│   └──────────────────────────────────────────────────────────┘   │
└──────────────────────────────────────────────────────────────────┘
```

**为什么不用卡片**：远程包没有封面（服务器只给文件名和 title ID），做成卡片是一排灰色空框，比行更难看。行还多一个好处——能放下文件名，用户靠它认游戏。

### 决策二：下载不阻塞库页

**用户的真实动作**：点下载 → 等 → 走开去干别的 → 回来。

所以下载**不能是模态**。用已有的 `ImportBanner`（顶栏下方一条细带）：
- 一条带子，显示进度、速度、剩余
- 用户可以继续浏览、点别的游戏、进设置
- 下载在后台跑（ArkTS 的 `requestInStream` 本来就是异步的）

**唯一阻塞的时机**：导入（解包 1230 个文件）。那时给一个 `ImportPanel` 模态，因为文件系统在密集写。

### 决策三：源地址是一个"连接"，不是一段配置

现在的实现是设置页一个输入框。但用户的心智模型是**连一台服务器**：

```
未连接 → [连接服务器] → 输入 192.168.2.2 → 探测 → 已连接（显示包数）
```

- 输入后立刻探测 `/ping`，成功才保存
- 失败给**具体原因**（连不上 / 没有 /list / 返回格式不对），不是"保存失败"
- 已连接状态在库页可见（区标题右侧显示地址），点一下能重连

### 决策四：管理用长按，不用常驻按钮

已安装卡片的删除、存档管理，走**长按 → GameDetailSheet**（S2 已有的组件）。
不在卡片上放常驻删除按钮：误触代价太大（删掉 14.7 GB）。

## 3. 状态机

### 远程包一行

```
   Idle ──点下载──→ Downloading ──完成──→ Importing ──完成──→ Installed
    ↑                    │                    │
    │                    ↓                    ↓
    └──── 失败 ──── Failed ←──────────────────┘
                        │
                     点重试
```

| 状态 | 显示 | 可点 |
|---|---|---|
| Idle | `[下载]` | 是 |
| Downloading | 百分比 + 进度条 | 是（取消） |
| Importing | `导入中` + 转圈 | 否 |
| Installed | `✓ 已安装` | 否（点了进游戏） |
| Failed | 红色原因 + `[重试]` | 是 |

**断点续传**：`Downloading` 中断后回到 Idle，但 `have > 0`，再点时发 `Range` 头续传。
用户看到的是"下载"按钮，实际是从断点继续——**不需要单独一个"继续"状态**，少一个概念。

### 服务器连接

```
NoSource ──填地址──→ Probing ──成功──→ Connected ──刷新失败──→ Stale
                        │                                        │
                        └──失败──→ Unreachable ←─────重试─────────┘
```

`NoSource` 时整个「可下载」区**不渲染**——没配服务器的设备，看起来和 S2 完全一样。

## 4. 视觉规格

### 4.1 「可下载」区

| 元素 | 规格 |
|---|---|
| 区标题 | `Font.label` / `Text.secondary` / 左侧 |
| 地址 | `Font.caption` / `Text.tertiary` / 右侧 |
| 刷新 | `Font.label` / `Semantic.accent` / 点击刷新 |
| 分隔线 | 1px / `Bg.elevated` |
| 行高 | 64（两行文字：文件名 20 + 元信息 16 + padding 28） |
| 行背景 | `Bg.card` / `Radius.md` |
| 行间距 | `Space.s2` = 8 |
| 行内 padding | `Space.s3` = 12 水平 |
| 文件名 | `Font.body` / `Text.primary` / 单行省略 |
| 元信息 | `Font.caption` / `Text.tertiary` |
| 操作按钮 | `Font.label` / `Semantic.accent` / 宽 72 / 右对齐 |
| 失败文字 | `Font.caption` / `Semantic.danger` |

### 4.2 进度条（行内）

下载中那一行变成：

```
┌──────────────────────────────────────────────────────────┐
│  Celeste.nxpk                          1.17 GB   42%     │
│  ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░  2.1 MB/s · 剩余 8 分 30 秒  │
└──────────────────────────────────────────────────────────┘
```

- 进度条：高 3 / `Semantic.accent` / `Radius.full` / 占满行宽
- 百分比：`Font.label` / `Semantic.accent`
- 速度与剩余：`Font.caption` / `Text.tertiary`

**速度与剩余时间**是这一区最该有的信息：1.17 GB 在 Wi-Fi 上要几分钟，没有 ETA 用户不知道要不要等。

### 4.3 空状态

配了服务器但没有包：

```
可下载                                    192.168.2.2
  这台服务器上没有游戏包
```

连不上：

```
可下载                                    192.168.2.2  [重试]
  连不上：Failed to connect to the server
```

## 5. 交互细节

### 5.1 点「下载」

1. 行进入 `Downloading`，按钮位置换成百分比
2. 顶栏下出现 `ImportBanner`（细带，可继续操作）
3. 下载完成 → 行进入 `Importing`，弹出 `ImportPanel`（模态）
4. 导入完成 → 行进入 `Installed`，主网格多一张卡片（带 200ms 淡入）

### 5.2 离开库页

下载中用户可以：
- 进设置页 → 下载继续
- 进游戏 → 下载继续（`requestInStream` 在 ArkTS 侧是独立任务）
- 返回库页 → 行仍显示当前进度（状态从模块级单例读，不是组件内 state）

**这一条要求下载状态活在组件外**。现在的 `RemotePacksSection` 把状态放在 `@State rows` 里，页面销毁就丢了。
**改**：状态放模块级单例（`RemoteDownloads`），组件只订阅。

### 5.3 取消下载

点 `Downloading` 行的百分比区域 → 确认框「取消下载？已下载的部分会保留，下次从断点继续」。

### 5.4 已安装的远程包

行变 `✓ 已安装`，不可点。
如果用户在本地删了这个游戏，行回到 `Idle`（下次刷新时比对 stamp）。

## 7. 验收标准

- [ ] 没配服务器时，库页和 S2 完全一致（不多一个像素）
- [ ] 填地址点连接，3 秒内给出成功或**具体失败原因**
- [ ] 点下载，顶栏出现细带，可以继续浏览别的游戏
- [ ] 离开库页再回来，进度还在
- [ ] 下载中断后重试，从断点继续（服务端日志有 `206`）
- [ ] 下载完成自动导入，主网格出现新卡片
- [ ] 已安装的行显示 `✓`，重复点不会重下
- [ ] 长按已安装卡片 → 详情 → 能删除

---

## 8. 不做的事

- **不做多服务器**：一个源够用，多源是管理负担
- **不做自动发现**（mDNS）：手填一次 IP 比等发现快
- **不做断点续传的独立按钮**：状态机里 Idle 就是"可续传"
- **不做远程包的封面**：服务器没有，编不出来
- **不做后台服务下载**：ArkTS 的 http 在应用进程内，进程被杀就停。文档里写清楚，不假装能做到。
