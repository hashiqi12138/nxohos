## 1. 这一屏要解决什么

**用户打开应用的第一眼。** 他要在一秒内回答三个问题：

1. 我有哪些游戏？
2. 哪个能玩？
3. 怎么开始？

**不解决的问题**：设置、存档管理、商店、社交。这一屏只做"看到 + 启动"。

## 2. 布局：三种屏幕形态

### 2.1 横屏大屏（主场景，≥ 900 vp 宽）

**这是产品的主界面。**

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│  NXOHOS                                        [＋ 添加游戏]      │ ← 顶栏 64
│                                                                  │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│   │          │  │          │  │          │  │          │       │
│   │    Z     │  │    M     │  │    S     │  │    ＋    │       │
│   │          │  │          │  │          │  │          │       │
│   │          │  │          │  │          │  │  添加    │       │
│   ├──────────┤  ├──────────┤  ├──────────┤  ├──────────┤       │
│   │塞尔达     │  │马力欧     │  │斯普拉遁   │  │          │       │
│   │14.7 GB   │  │8.2 GB    │  │6.1 GB    │  │          │       │
│   │● 可运行   │  │● 可运行   │  │● 可运行   │  │          │       │
│   └──────────┘  └──────────┘  └──────────┘  └──────────┘       │
│                                                                  │
│                                                                  │
│                      ● ○ ○                                       │ ← 分页 40
└──────────────────────────────────────────────────────────────────┘
```

**尺寸计算**（1260 vp 宽参考）：
- 左右 padding `Space.s6` = 32 → 可用 1196
- 4 卡片 + 3 间距(24) = 1196 → 卡片宽 = (1196 - 72) / 4 = **281**
- 封面 1:1 → 281×281
- 卡片总高 = 281 + 文字区(72) = 353
- 顶部 64 + 内容 padding 24 + 353 + 分页 40 + 底部 32 = 513 < 560 ✅ 放得下

### 2.2 横屏小屏（600-900 vp）

3 列。卡片宽 = (可用宽 - 2×24) / 3。

## 3. 顶栏

```
NXOHOS                                    [＋ 添加游戏]
```

| 元素 | 规格 |
|---|---|
| 高度 | 64（横屏）/ 56（竖屏） |
| 背景 | `Bg.base`，底部 1dp `Semantic.borderSubtle` |
| 品牌 | `NXOHOS`，`Font.title`，`Text.primary`，字重 Medium，字距 +0.5 |
| 添加按钮 | `Button` primary 变体，`Size.buttonMd`（40 高），图标 + 文字 |

**为什么品牌字在左上角**：产品需要身份感。不是"文件管理器"，是"NXOHOS 游戏库"。

**添加按钮为什么在右上**：右上是主操作区（右手拇指易达，手柄导航的终点）。

## 4. 游戏卡片

### 4.1 结构

```
┌────────────────────┐
│                    │  ← 封面区 1:1
│                    │     有 icon：Image fill, objectFit Cover
│         Z          │     无 icon：哈希底色 + 首字（56sp, 22% 白）
│                    │
│                    │
├────────────────────┤  ← 1dp borderSubtle
│ 塞尔达传说          │  ← Font.body, Text.primary, 最多 1 行省略
│ 王国之泪            │     （第二行留给副标题，见下）
│ 14.7 GB · ● 可运行  │  ← Font.label, Text.secondary + 状态点
└────────────────────┘
```

**文字区高度固定 72**（body 24 + label 20 + padding 16×2 - 4），防止不同长度名字导致卡片高度不齐。

### 4.2 状态矩阵

| 状态 | 封面 | 边框 | 缩放 | 阴影 | 文字 | 可点 |
|---|---|---|---|---|---|---|
| **默认** | 100% | 无 | 1.0 | 无 | primary / secondary | ✅ |
| **焦点** | 100% | 2dp `accent` | **1.06** | 8dp `accentGlow` | primary / secondary | ✅ |
| **按下** | 92% 亮度 | 无 | **0.97** | 无 | 同上 | ✅ |
| **不可用** | 40% 不透明 | 无 | 1.0 | 无 | tertiary / tertiary | ❌ |
| **启动中** | 覆盖 `overlay` + 环形进度 | 无 | 1.0 | 无 | "正在启动" | ❌ |
| **校验中** | 100% | 2dp `warning` | 1.0 | 无 | "正在校验" | ❌ |

**焦点 vs 按下优先级**：焦点态下按下 → 显示按下效果（0.97），松开后回到焦点（1.06）。

### 4.3 交互

| 手势 | 行为 | 反馈 |
|---|---|---|
| 单击/轻触 | 启动游戏 | 按下 0.97 → 松开进"启动中" |
| 长按 600ms | 打开详情抽屉 | 震动（`vibrator` 短震）+ 抽屉滑入 |
| 手柄 A | 启动焦点卡片 | 同单击 |
| 手柄菜单键 | 打开焦点卡片详情 | 同长按 |

**长按阈值 600ms**：短于 400ms 容易误触，长于 800ms 感觉迟钝。

### 4.4 添加游戏卡片

**永远在列表末尾**，和游戏卡片同尺寸：

```
┌────────────────────┐
│                    │
│        ＋          │  ← 48sp, Text.tertiary
│                    │
│      添加游戏       │  ← Font.body, Text.secondary
│                    │
└────────────────────┘
```

- 背景 `Bg.card`，**虚线边框** 1dp `Semantic.borderSubtle`（区别于实心游戏卡片）
- 焦点/按下规则同游戏卡片
- 点击 → 文件选择器

**为什么放在列表里而不是只放顶栏**：空库时它是唯一的行动点；有游戏时它是"下一个动作"的自然延伸。

## 6. 焦点系统

### 6.1 网格导航

```
← →   同行移动，到行尾不换行（停在最后一个）
↑ ↓   同列移动；下行不足时停在该行最后一个
Home  第一个
End   最后一个
```

**边界不循环**：在第一个按 ← 不动。循环会让人失去位置感。

**行尾行为**：4 列布局，第 2 行只有 2 个卡片时，从第 1 行第 4 个按 ↓ → 落到第 2 行第 2 个（不是第 4 个，因为不存在）。

### 6.2 焦点视觉

```
默认卡片           焦点卡片
┌────────┐        ╭────────╮  ← 2dp accent
│        │   →    │        │     8dp accentGlow
│   Z    │        │   Z    │     放大 1.06
└────────┘        ╰────────╯
```

**过渡**：旧卡片缩回 + 新卡片放大，同时 200ms `Motion.base`。

**焦点始终可见**：即使刚触摸过屏幕，焦点环不消失（手柄和触摸混用时不会迷失）。

### 6.3 初始焦点

| 场景 | 焦点位置 |
|---|---|
| 首次打开（有游戏）| 第一个游戏卡片 |
| 从游戏退出回库 | 上次启动的游戏卡片 |
| 空库 | 添加游戏按钮 |

## 7. 启动流程

```
点击卡片
  ↓
卡片进入"启动中"（遮罩 + 环形进度 + "正在启动"）
  ↓
startOnce():
  ├─ migrateLegacySandbox（首次）
  ├─ refreshLibrary
  ├─ stageData → stamp 比对
  │    ├─ 匹配 → 直接启动
  │    └─ 不匹配 → 走导入流程（S3）
  └─ startGame(root, save, cache)
  ↓
成功：XComponent 显示游戏画面，卡片消失（全屏）
失败：卡片退出"启动中"，红边 2s，Toast 说明原因
```

**启动中的等待**：从点击到第一帧约 3-8 秒。必须给反馈，否则用户以为没响应。

**失败恢复**：游戏进程可能已经启动但崩溃。检测方式：`startGame` 后 5 秒内如果没有 `game thread started` 日志 → 判定失败。

## 8. 加载与骨架屏

| 时长 | 表现 |
|---|---|
| < 200ms | 无反馈（直接显示内容）|
| 200ms - 1s | 骨架屏：3 个卡片轮廓（`Bg.card` 20% 不透明）+ 微光从左到右扫过（1.2s 循环）|
| > 1s | 骨架屏 + 底部小字"正在读取游戏库…" |

**为什么 200ms 门槛**：低于此的加载显示 spinner 会造成闪烁，比不显示更糟。

**库扫描耗时**：`listGames` 对每个游戏做 `treeSize`（60000 条目预算）。单游戏约 50-100ms，5 个游戏 500ms。**超过 200ms 是常态**，所以骨架屏是主要路径。

**优化**：把体积缓存在 `<root>/.meta.json`（导入完成时写入），列表只读缓存。这样 `listGames` 只需读文件 + `statSync`，降到 <50ms。

## 14. Visual pass (2026-11-16)：真机截图后的重设计

第一版实现上机后（[s2_current.jpg](../../../../.screenshots/s2_current.jpg)）暴露了三个视觉问题：

1. **占位封面**：一个巨大的字母 `T` 立在纯色块中央——像系统占位图，不像游戏产品。
2. **卡片结构**：游戏名直接糊在方块的下半部分——像文件列表，不像主机启动器。
3. **整体氛围**：纯平深底、无环境光、焦点环千篇一律的粉色——每个游戏看起来一样。

### 修正方向（参考 Switch 主界面 + Apple TV 环境光）

| 问题 | 决策 | 理由 |
|---|---|---|
| 封面结构 | **封面即卡片**：圆角方块（radius 20）只承载艺术品；游戏名和元数据移到方块**下方、外部、居中**（Switch 式） | 主机启动器的语言；文字脱离方块后卡片变成纯粹的"游戏之窗" |
| 占位封面 | **渐变底 + 字母水印**：底色从 `palette[i]` 到 `darken(palette[i], 0.55)` 的对角渐变；首字母改为右下角大号（封面尺寸×0.62）水印，12% 白 | 字母从"主角"降为"纹理"；渐变给纯色块以深度 |
| 焦点视觉 | 焦点环改为**白色 2dp**（不再粉色）；光晕颜色改为**焦点游戏自己的 palette 色**（`rgba(color, 0.45)`，radius 32）；缩放 1.08 | 每个游戏有自己的氛围色，切焦点时整个界面"变色"——这是 Switch/Apple TV 的核心质感；白色环是中性容器，不与任何游戏色冲突 |
| 环境光 | 背景层叠一个**全屏线性渐变**：焦点游戏的 palette 色 16% → 5% → 0 透明，160° 角，400ms 过渡 | 深底不再纯平；焦点在哪，光就在哪 |
| 卡片间距 | `rowsGap`/`columnsGap` 提升到 28 | 封面圆角方块需要呼吸空间 |
| 顶栏 | 去掉底部分隔线，让环境光贯通 | 分隔线打断氛围 |

**不变**：焦点导航规则（边界不循环）、断点计算、`.meta.json` 缓存、启动流程、双轴尺寸公式（`cover = min(fromWidth, fromHeight - caption)`）。

### Tokens 新增

```
CoverPalette.rgba(hex, a)      // #RRGGBB → rgba(r,g,b,a)，供渐变/光晕
CoverPalette.darken(hex, f)    // #RRGGBB × f → 更深的同色系，供渐变底
```
