> 状态：性能采集已打通并实测两个游戏；客户端展示待实现
> 时间：2026-11-22 ｜ 设备：HUAWEI PBN-AL80（1260×2844，Maleoon 910）

## 一、先说结论：现状的三个断点

你要的“每个游戏都有性能测试、实际画面、用户能看到”，现在断在三处：

| 环节 | 现状 | 断在哪 |
|---|---|---|
| 采集 | hilog 有完整帧数据 | `measure.py` 要 `DM_VK_PROF_SLOW=1` 才有 sets 行，否则直接退出 |
| 存储 | 无 | 没有任何地方落盘，进程结束数据就没了 |
| 展示 | 无 | 客户端 grep `perf.json` / `PerfRecord` **零命中** |

也就是说：**数据一直有，但从来没有被保存，也从来没有被显示过。**

## 二、整体设计：三层数据 + 一条链路

```
采集层                 存储层                        展示层
─────                 ─────                        ─────
perf_capture.py  →  <filesDir>/games/<titleId>/  →  库卡片角标
  ├ fps                ├ perf.json（性能）            详情页性能表
  ├ frameMs p50/p95    ├ icon.jpg（封面）             详情页大图
  ├ gpuMs              └ shots/*.jpg（实际画面）
  └ slow%
```

**关键约束：所有产物都放游戏根目录，不放 `mods/`、`RomFS/`、`aoc/`。**

因为 `PackImport.ets:135` 只清理这三个目录。放根目录意味着**重新导入游戏数据不会丢掉测量记录和截图**。

## 三、性能指标：测什么、为什么

### 三个必测指标

| 指标 | 含义 | 为什么必须有 |
|---|---|---|
| **fpsP50** | 每秒帧数中位数 | 玩家感知的主指标，但不该用平均值——一秒掉帧会被平滑掉 |
| **frameMs p50 / p95 / max** | 帧时间中位/95分位/最大 | p95 才是“卡不卡”的真相。p50 好看但 p95 炸，玩起来就是顿 |
| **slow%** | 超过 33.3ms 的帧占比 | 直接对应“每秒掉到 30 以下的比例”，比 fps 更能说明体感 |

### 两个辅助指标

| 指标 | 含义 | 说明 |
|---|---|---|
| **gpuMsP50** | GPU 时间戳跨度 | 判断瓶颈在 GPU 还是 CPU |
| **frames** | 累计帧号 | 验证测量窗口真实有效，不是空转 |

### 一个诚实原则

**没有测到的字段写 `-1`，绝不写 `0`。**

写 0 会让“没测”看起来像“性能极好”。`-1` 让缺失显式可见，UI 显示“未测”。

## 五、场景标注为什么重要

同一个游戏，标题画面和实际游戏内性能可能差 5 倍。

`--scene` 参数强制标注，因为：
- 标题画面通常负载低，不能代表可玩性
- 必须分别记录 `title` / `shrine` / `field` 等场景
- 详情页要显示场景名，否则用户不知道这个数字是什么状态下的

## 六、采集器：为什么不用现成的 measure.py

`measure.py` 有两个硬问题：

1. **要 `DM_VK_PROF_SLOW=1`**：没有就直接退出 `no "sets (present ...)" counter line`
2. **`hilog -x` 不会自己退出**：它是流式命令，`subprocess.run` 会等到超时然后**丢掉已读到的全部输出**

所以写了 `dm/ohos/perf_capture.py`：
- 只读永远存在的两行：`timing up to frame N: frame time p50/p95/max` 和 `fps: N frames/s`
- `hdc_run` 用 `Popen` + 超时后 `kill()`，**保留已读到的输出**
- 设备分辨率从 `hidumper -s RenderService -a screen` 读（`wm size` 在这台机器上不存在）

### 卡片层

在 `GameCard` 上加一行性能角标：

```
┌──────────────┐
│   封面图      │  ← icon.jpg（已有）
│              │
│  [60 fps]    │  ← 新增：fpsP50，颜色按阈值
```

颜色规则：
- `≥55 fps` → `Semantic.success` 绿
- `30–55` → `Semantic.warning` 黄
- `<30` → `Semantic.danger` 红
- 无数据 → `Text.tertiary` 灰，显示「未测」

## 九、必须告诉你的三个风险

1. **TOTK 只有 8 fps**：这不是测量问题，是真实的性能。要提升需要查 GPU 瓶颈（82.4ms），不是改展示能解决的。

2. **`pack_game.py` 改动会让旧包 stamp 失效**：因为打包顺序变了（元数据提前）。设备上已装的包会被判定需更新。这是预期行为。

3. **重装 HAP 不会刷新已有游戏的 `.meta.json`**：缓存按 stamp 判断有效，stamp 没变就继续用旧缓存。所以改名字/封面后，需要重新导入才会生效。这个行为要写进文档，否则用户会困惑。
