## 交付物

### 需求条目

**REQ-IMPORT-RETRY-001：失败态提供重试入口**  
- 动机：当前导入失败只有红色提示，用户无恢复路径。  
- 验收条件：  
  - 导入失败时，失败提示区域显示“重试”按钮。  
  - 点击“重试”后，在失败态原地发起重试，不要求用户重新选择文件/来源。  
  - 重试请求期间按钮禁用，并显示“重试中…”或等价加载态。  
  - 若重试再次失败，保留失败态并更新错误摘要。  
- 明确不做什么：  
  - 不做自动重试，必须由用户手动触发。  
  - 不改变导入成功后的现有交互。

**REQ-IMPORT-RETRY-002：失败上下文保留**  
- 动机：重试必须复用原导入参数，否则用户需重新配置。  
- 验收条件：  
  - 失败后保留导入来源（文件路径/链接/账号授权等）及解析选项。  
  - 当前会话内未关闭页面时，上下文可复用。  
  - 页面刷新后是否恢复失败态，需与产品确认；本条目暂不要求持久化。  
- 明确不做什么：  
  - 不持久化失败文件内容到本地磁盘。  
  - 不恢复已过期或失效的授权令牌。

**REQ-IMPORT-RETRY-003：错误信息可读与重试约束**  
- 动机：用户需要知道失败原因，系统需要避免无效重试。  
- 验收条件：  
  - 失败态显示可读错误摘要，包含错误码/原因。  
  - 对可重试错误（网络超时、临时文件锁、5xx）启用“重试”。  
  - 对不可重试错误（格式损坏、权限拒绝）禁用“重试”，并给出处理指引。  
- 明确不做什么：  
  - 不向用户暴露堆栈或内部日志。  
  - 不屏蔽后端返回的原始错误码，但需在 UI 层映射为可读文案。

**REQ-IMPORT-RETRY-004：重试次数与频控**  
- 动机：避免用户反复点击造成请求压力。  
- 验收条件：  
  - 连续手动重试达到 3 次后，提示“请稍后再试”。  
  - 若后端返回 429 或明确限流，失败态直接提示稍后再试，并禁用重试按钮至建议时间。  
  - 不实现客户端自动退避轮询。  
- 明确不做什么：  
  - 不做无限重试。  
  - 不做自动指数退避，除非产品另有要求。

**REQ-IMPORT-RETRY-005：埋点与可观测性**  
- 动机：衡量导入失败率与重试成功率。  
- 验收条件：  
  - 上报导入失败事件，字段包含导入任务 ID、错误码、失败时间。  
  - 上报重试点击事件，字段包含任务 ID、重试次数。  
- 明确不做什么：  
  - 不采集用户文件内容或文件路径全名。

### 冲突与依赖清单

1. **依赖导入 API 支持幂等/任务 ID**：若后端没有任务 ID 或不可重复提交，重试只能重新发起全新导入，需确认后端能力。  
2. **冲突：现有红色提示组件**：需先定位现有失败提示实现，是全局 toast/alert 还是页面内联提示；改造可能涉及组件库升级或局部替换。  
3. **冲突：多入口不统一**：若导入入口包括拖拽、文件选择、URL 导入等，失败态需覆盖所有入口，否则会存在无重试入口的遗漏路径。  
4. **依赖错误码分类**：若后端未返回结构化错误码，无法区分可重试/不可重试错误，需先补齐错误码枚举。  
5. **冲突：可能已有后台重试**：若导入流程已有服务端重试或轮询，需避免客户端重复触发。  
6. **刷新恢复边界**：若产品要求刷新后仍能重试，需要失败任务持久化或路由状态保存，当前需求未包含，需确认范围。
