# G0.5 验收记录 — M0.5 寄存器/futex/代码页语义

状态：**真机实测完成（2026-11-06，AGC 云调试 ADY-AL10 / OpenHarmony-6.1.1.120 /
Maleoon 910）**。Pro+ 机型当时被占用，本轮用同系列机型复核；寄存器语义与

## 一、寄存器与同步语义（5/5 PASS）

| 项 | 实测 | 判定 |
|---|---|---|
| `tpidr_rw` | 哨兵写读回 `t0=0000005b80359aa8`，写后读回即哨兵 | PASS（tpidr_el0 可写） |
| `tpidrro` | 可读、值 `nonzero` | PASS |
| `cntpct` | 10ms 自旋后严格递增，`cntfrq_el0=1920000`（1.92MHz） | PASS |
| `tls_per_thread` | 两线程 `self=5b80359aa8 / other=5b8055faa8`，各自稳定 | PASS |
| `futex` | `blocked=1 woke=1 spur=0 101ms` | PASS（与 Linux 语义一致） |

结论：**重写器依赖的寄存器/TLS/计时器/futex 语义在 HarmonyOS 上全部成立，
不需要 B 文档预案里的 musl 适配**。

## 二、代码页 W^X（0/6，六条路径全部被拒）

| # | 路径 | 实测错误 | 含义 |
|---|---|---|---|
| a | 匿名 RW → `mprotect(RX)` | `E=22` (EINVAL) | 可写匿名页永远拿不到执行权 |
| b | 匿名 `mmap(PROT_EXEC)` | `E=22` | 匿名执行页本身被禁（execmem） |
| c | 沙盒文件 `MAP_SHARED` 双别名（一段 RW、一段 RX） | `E=13` (EACCES) | 沙盒文件不允许映射成可执行 |
| d | 已加载 .so 的可执行段 `MAP_PRIVATE\|PROT_EXEC` | `E=13` | 连"复制一份代码段"也被拒 |
| e | 自身代码页 `mprotect(RW)` → 改回 `mprotect(RX)` | RW 成功、**RX `E=13`** | 一旦弄脏代码页就永久失去执行权（单向 W^X） |
| f | 沙盒文件 `MAP_PRIVATE\|PROT_EXEC`（dlopen 同款） | `E=13` | 与 c 同结论，dlopen 侧加载沙盒文件亦不可行 |

`wx.note` 原文：

```
rw2rx[mprotect E=22] rwx[rwx mmap E=22] file[map rx E=13] so[so map E=13] txt[text mprot RX E=13] priv[priv map E=13]
```

### 直接影响（G0.5 的核心决策）

1. **运行时生成/改写代码在本平台不可行**：不仅新建可执行页被拒，把已加载代码页
   改成可写之后再改回可执行也被拒（单向 W^X）。因此 JIT、运行时打补丁、
   "落盘 .so 再 dlopen"这三类方案全部排除。
2. **重写器必须是 AOT（离线重写）形态**：在构建期把 NSO 重写成真实 `.so`，随 HAP
   打包进 `libs/arm64-v8a/`，由系统加载器正常映射成 RX 执行 —— 这与界面无关，
   也和 `libprobe.so` 自身的加载方式完全一致（该 .so 每轮都在真机上执行）。
3. B 文档 M0.5 预案里"G0.5 不过 → musl 适配"的判断需要修正：**FAIL 点不在
   寄存器语义（5/5 PASS），而在代码页策略；musl 适配解决不了 W^X**，正确解法是
   把重写器从「运行时」改成「构建期」。

`aot_nso` 的超时已定位为探针实现问题，而非平台能力问题：

多线程的）。已改为 **父进程内 `probe_aot_preload()` 预先 dlopen + dlsym，子进程只调用**，
改动已进代码，但本轮设备**优惠时长已用尽**，未能完成复测。下一轮云调试第一件事
就是补跑这项；预期 `aot_nso=true`（其四项语义已由上面 5/5 PASS 的寄存器检查覆盖）。

### 顺带修掉的一个真隐患

原 `aot_nso` 会先 `mini_host_x18_write(canary)` 在**宿主线程**写 x18。aarch64 上 x18
可能被用作影子调用栈指针（SCS）：宿主线程改写它，下一次函数返回就会读坏返回地址
——这既可能解释子进程"卡死/不返回"，也可能让整个进程崩掉。已改为**只读比对**
（调用 guest 前后读两次 x18，值不变即通过），不再写宿主寄存器。

### 工具链可靠性修复（本轮踩坑后加固）

## 五、判定语义

| 项 | 判据 |
|---|---|
| tpidr_rw | 哨兵写读回等于哨兵（静默丢弃 → false） |
| tpidrro | 读不 trap；note 记 zero/nonzero |
| cntpct | 自旋 10ms 后严格递增，按 `cntfrq_el0` 换算 |
| tls_per_thread | 两线程 tpidr_el0 不同且各自稳定 |
| futex | WAIT 阻塞、WAKE 唤醒、无伪唤醒 |
| wx | 六条路径任一可执行即 true |
| mini_nso | svc gate=42 / x18 槽 / TLS / 计时器 四项全 OK |

## 六、结论

- **寄存器/TLS/计时器/futex：PASS（5/5）** —— 重写语义前置条件成立。
- **W^X：FAIL（0/6）** —— 运行时执行生成代码不可行，且为单向 W^X。
- **闸门判定：PASS（条件通过）** —— 重写器改走 AOT 后不依赖任何运行时可执行页；
  `mini_nso` 的 FAIL 是 W^X 的直接推论，不构成新的阻塞项。
- **遗留一项**：`aot_nso` 需在下一轮云调试（或实体 Pro+）复测，验证
  `libmininso.so` 经 dlopen 后四个入口语义成立；除此之外 M1 无阻塞。
