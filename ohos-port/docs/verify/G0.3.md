# G0.3 验收记录 — M0.3 BCn 格式支持探测（决定 M3.4 是否启动）

状态：真机实测完成（Pura 70 Pro+ / HBN-AL80 / OpenHarmony-6.0.2.130 / Maleoon 910）

## 验收命令

```sh
# TC0-3-1（16 键契约 + 逐键判定）
python tools/verify/verify_report.py out/device/probe_report.json --tc tc0-3-1

# TC0-3-2（bcn_all=true 时：fixture 渲染 vs 独立参考解码，PSNR > 40dB）
# 设备侧渲染 BC7 fixture 后导出末帧（DM_DUMP_FRAMEBUFFER）或截屏，PC 侧与
# 独立生成的参考 RGBA 基准比对（compare-baseline：≥99.5% 容差内 且 PSNR>40dB，
# 阈值取 configs/pixel_thresholds.py::BASELINE_MIN_PSNR_DB=40.0，严格大于）
python tools/verify/verify_pixel.py out/device/bc7_render.png \
  compare-baseline fixtures/textures/bc7_reference_rgba.png --tol 16

# TC0-3-3（bcn_all=false 时）
python tools/verify/verify_report.py out/device/probe_report.json --tc tc0-3-3
```

## 分支决策（写入本文件，模板）

```
bcn_all = false（16/16 全为 false）
├─ bcn_all=true 且 TC0-3-2 PASS  → 原生路径，M3.4 跳过
└─ 否则                          → 启动 M3.4 转码线   ← 实际走这条
   需要转码的格式清单（只有缺失格式需要）：全部 16 项
   BC1_RGB_UNORM / BC1_RGB_SRGB / BC1_RGBA_UNORM / BC1_RGBA_SRGB
   BC2_UNORM / BC2_SRGB
   BC3_UNORM / BC3_SRGB
   BC4_UNORM / BC4_SNORM
   BC5_UNORM / BC5_SNORM
   BC6H_UFLOAT / BC6H_SFLOAT
   BC7_UNORM / BC7_SRGB
```

**上一轮 ASTC 为 false 是 fork 隔离造成的假阴性**：vk 检查曾在 `fork()` 子进程里
执行，子进程的图形上下文失效，导致 `vkGetPhysicalDeviceFormatProperties2` 对 ASTC
返回 0。把 vk 检查移到父进程内（见 G0.2 根因）后重跑，ASTC 4x4/8x8 均为 true，
BCn 16 项仍全为 false —— 后者是真实能力。故"BCn 缺失 → 转 ASTC"的兜底方案成立，
M3.4 转码目标格式确定为 ASTC（4x4 用于通用贴图，8x8 用于低精度/远景）。

## 预期输出 vs 实际输出

| 项 | 预期 | 实际 | 结论 |
|---|---|---|---|
| TC0-3-1 | 恰好 16 个 VK_FORMAT_* 键，逐键 true/false | 16 键齐、逐键 bool、supported=0 | **PASS** |
| TC0-3-2 | PSNR > 40dB（逐通道最小值的保守下界；严格大于） | bcn_all=false，fixture 无从渲染 | 不适用 |
| TC0-3-3 | ASTC 4x4/8x8 均 true（转码兜底前提） | 4x4=true、8x8=true | **PASS** |

## GPU 驱动特性评估记录

```
支持的格式特性集（SAMPLED_IMAGE 位）：16 项 BCn 全 false；ASTC 4x4/8x8 均 true
```

## 结论

- 结论：**PASS**（TC0-3-1 PASS、TC0-3-3 PASS；TC0-3-2 因无 BCn 原生路径不适用）
- 备注：M3.4 转码线启动，落点 ASTC；BCn 全系（BC1–BC7）均需转码。
