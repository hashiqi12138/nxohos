# G0.4 验收记录 — M0.4 mmap 大地址预留

状态：**实测完成（2026-11-06，AGC 云调试；首轮机型 Pura 70 Pro+ / HBN-AL80 /
HarmonyOS 6.0.0.108，复核机 ADY-AL10 / OpenHarmony-6.1.1.120）**；
TC0-4-1 / TC0-4-2 均 PASS，TC0-4-3 需实体设备（投屏黑屏无法可靠切后台）。

## 云调试实测结论

| 检查 | 实测 | 判定 |
|---|---|---|
| `mem_reserve_5g`（5GB PROT_NONE） | `base=0x5bd7004000` | PASS |
| `mem_headroom_8g`（base+5GB 处 +8GB） | `MAP_FIXED_NOREPLACE` 返回 `E=38`（ENOSYS，平台未实现）→ 降级「先查 `/proc/self/maps` 确认区间空闲 → `MAP_FIXED`」后成功 | **PASS**（`fixed contig=1`） |
| `mem_commit_2g`（commit 2GB 后 memset） | `rss≈2.1GB`，进程存活 | PASS |

### 关键数据

```
mem_headroom_8g.note = "fixed contig=1 vm=53826348kB rss=21576kB"   （ADY-AL10 复核）
mem_headroom_8g.note = "fixed contig=1 vm=51942024kB rss=94300kB"   （HBN-AL80 首轮）
mem_commit_2g.note   = "commit ok=1 vm=45437736kB rss=2118684kB"
```

即 **13GB 连续虚拟布局在真机上可以做到**，条件是：
1. 不能依赖 `MAP_FIXED_NOREPLACE`（平台返回 E=38）；
2. 用「`/proc/self/maps` 预检区间空闲 + `MAP_FIXED` 钉死」两步走；
3. 兜底可一次性 `mmap` 13GB（单次映射天然连续）。

### 对 dmhost loader 的直接影响（G0.4 的关键决策）

M1.1 loader 采用「先 5GB 预留 → 读 maps 确认 base+5GB 空闲 → `MAP_FIXED` 接 8GB」
的落位算法；若预检发现被占，回退「一次性 13GB 整体预留」。**不需要**双映射别名
或影子地址表方案。

> 结论：G0.4 判 **PASS**（TC0-4-1 PASS、TC0-4-2 PASS）；仅 TC0-4-3（前后台/冻结）
> 因云调试投屏黑屏无法执行，留待实体设备验证，不阻塞 M1。


## 验收命令

```sh
# TC0-4-1（report 判定：5GB 预留 + 8GB 精确衔接连续）
python tools/verify/verify_report.py out/device/probe_report.json --tc tc0-4-1

# TC0-4-2（commit 2GB 存活 + VmSize/RSS 外部观测）
# 1) 带观测窗口重建/触发探针：DM_MEM_HOLD_SECS=30（≤50，父进程 60s 超时兜底）
# 2) 探针运行期间另开 shell，找到 mem 检查子进程后采样：
sh tools/verify/readmem.sh <pid>   # 设备侧执行（/proc 访问），或：
hdc shell "cat /proc/<pid>/status | grep -E 'VmSize|VmRSS'"

# TC0-4-2 LMK 断言（commit 期间探针进程未被 lowmemorykiller 杀）
python tools/verify/assert_hilog.py --file out/device/hilog.txt \
  --must-not 'lowmemorykiller'

# TC0-4-3（切后台 60s 后回前台：探针进程存活 + 后台限制行为留档）
# 1) aa start 探针并等待 mem 检查进行中
# 2) hdc shell uitest uiInput keyEvent Home（或 uinput 按键）切后台
# 3) sleep 60 后回前台（aa start 再次拉起同 ability）
# 4) 记录探针是否存活（hilog 'probe:' 连续输出 / report 是否完整落盘），
#    记录系统是否冻结（hilog 出现 RenderService/FFRT suspend 字样）
# 结论与对策留档（关联 M2.4 前后台与冻结时钟），不设硬 PASS/FAIL 阈值
```

## 预期输出 vs 实际输出

| 项 | 预期 | 实际 | 结论 |
|---|---|---|---|
| TC0-4-1 | `reserve_5g=true`、`reserve_headroom_8g=true`、`headroom_contiguous=true`（三值同真才 PASS——headroom 段返回地址与 base+5GB 精确相邻） | `reserve_5g=true`（base=0x5bd7004000）；`reserve_headroom_8g=true`、`headroom_contiguous=true`，note=`fixed contig=1 vm=53826348kB rss=21576kB`（NOREPLACE E=38 → maps 预检 + MAP_FIXED 降级成功） | **PASS** |
| TC0-4-2 | commit 段期间进程存活；VmSize ≥ 13GB（headroom 观测窗口）或 RSS ≈ 2GB（commit 观测窗口）；LMK 无杀进程记录 | `commit_2g_ok=true`，note=`commit ok=1 vm=43576364kB rss=2194996kB`（VmSize ≈41.6GB、RSS ≈2.09GB），未崩溃 | **PASS**（commit 路径） |
| TC0-4-3 | 切后台 60s 回前台后探针存活、report 完整；系统冻结行为记录（结论与对策留档，关联 M2.4） | 未执行（云调试投屏黑屏，无法可靠切后台/回前台） | 留档（待实体设备） |

## 注意事项

- 默认（无 DM_MEM_HOLD_SECS）映射验证后立即释放，外部观测不到目标状态——
  观测时必须设置该环境变量重建 HAP。
- ASLR 下 base 每次不同，`note` 字段记录 base=%p 供留档。

## 结论

- 结论：**PASS**（TC0-4-1 PASS；TC0-4-2 PASS；TC0-4-3 留档待实体设备）
- 备注：`MAP_FIXED_NOREPLACE` 平台不支持（E=38），但「maps 预检 + `MAP_FIXED`」
  可稳定拿到 13GB 连续布局，M1.1 loader 按此实现，不阻塞。
