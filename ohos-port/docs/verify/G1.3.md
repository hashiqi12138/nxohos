## 二、本轮修掉的两个崩溃（都在 demo 侧，不影响真实游戏路径）

### 1. SIGSEGV（pc == 故障地址，落在 libdmhost.so）

`dm/android/gfx_vk.h` 用 X-macro 给每个 Vulkan 入口生成了**与入口同名的全局函数
指针变量**（`extern PFN_vkX vkX`）。在 libdmhost.so 内直接写 `vkCreateInstance(...)`
会被链接器绑定到该**变量所在的地址（数据段）**，于是"调用"跳进数据段执行。

修法：demo 改为 `dlopen("libvulkan.so") + dlsym` 取到 `p_vkXxx` 再经指针调用
（`DM_VK_ENTRIES` / `DM_VK_LOAD` 宏）。真实游戏路径走 `gfx_vk_core.c` 的 `V` 表
（`VK_FNS` 赋值后再调用），不经过符号绑定，因此不受影响。

### 2. SIGABRT（`vkCreateSwapchainKHR` 内 abort，驱动直接终止进程）

demo 创建 VkDevice 时未启用 `VK_KHR_swapchain` 设备扩展；Maleoon 910 的驱动
在 swapchain 创建里直接 `abort()`，不返回错误码。修法：

- `VkDeviceCreateInfo.enabledExtensionNames` 加 `VK_KHR_swapchain`；
- 表面格式按「format + colorSpace 成对」选择（只比 format 会在某些驱动上选到
  不支持的组合）；
- `imageExtent` 按 `caps` 夹取；优先 `IDENTITY` transform（ROTATE_90/270 时交换宽高）；
  `compositeAlpha` 从 `supportedCompositeAlpha` 里挑；`usage` 加 `TRANSFER_DST`。

`gfx_vk_core.c` 的 `want[]` 本来就含 `VK_KHR_swapchain`，真实路径无需改动；
但 `ohos/gfx_vk_present_ohos.c` 的 format/extent/transform 选择应与上面的写法对齐，
留到 M1.5 接真实 present 时统一。

## 三、云调试通道的两个操作性结论（已写进脚本）

1. **控制台 HiLog 面板的关键字过滤读不到日志**（面板显示 `暂无数据`，同期
   `hilog -T dmhost -x` 有数据）。可靠通道是 Shell 面板里的
   `hilog -T <tag> -x`；脚本 `cloud_demo.py` 应改为从它取日志。
2. **控制台投屏在黑屏/隐私保护下是空白**，CDP 截 canvas 只能得到纯灰图。
   取真实画面要走设备侧：`snapshot_display -f /data/local/tmp/s.jpeg -w 690 -h 314`
   （可降分辨率），再用 `od -An -v -tx1 -j <off> -N <len>` 分段取回——
   `base64`、多命令 `;` 串联都被云 Shell 判为「无效命令或被限制执行」。
   690x314 的 JPEG 约 7.8 KB，两段各 4096 字节即可完整取回。
