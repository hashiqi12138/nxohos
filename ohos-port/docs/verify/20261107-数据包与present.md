## 1. 数据包：`mkhap.py --data`

```
python ohos/mkhap.py --game 01002B30028F6000 --data <数据目录> --out <输出目录>
```

- 数据整体拷到 `entry/src/main/resources/rawfile/dm`。
  **修正**：此前写的是 `entry/resources/rawfile`，hvigor 根本不打包（校验 HAP zip 时发现只有 `libs/arm64-v8a/libdmhost.so`，没有任何 rawfile 条目）。rawfile 必须位于模块的 `src/main/resources` 下。
- 生成 `entry/src/main/resources/rawfile/dm.files.tsv`：
  - 首行 `# DM_DATA <sha1>`（stamp），sha1 覆盖每个文件的 `相对路径 + 大小 + mtime_ns`（只用大小会让"同尺寸重建"的数据集命中旧拷贝）；
  - 其后每行 `相对路径\t大小`（页面不使用大小，留作人工核对）。
- ArkTS 运行时无法列 rawfile 目录，清单是唯一入口；首行同时充当版本戳。

## 2. 首启释放：`Index.ets stageData()`

流程：读 `dm.files.tsv` → 与 `files/dm/.stamp` 比对，相同直接返回 → 逐文件 `getRawFd` + 1 MiB 缓冲 `readSync/writeSync` 分块拷贝 → `closeRawFd` → 成功后写回 stamp。

- 分块是必须的：真实 RomFS 单文件可达数百 MB，`getRawFileContent` 整文件读入会 OOM。
- 返回三态：`none`（本构建没带数据）/ `ok` / `fail`；`fail` 时**不启动游戏**（避免半份数据被当成完整包启动）。
- 页面日志：`console.info` 在 `hilog -T <tag>` 下取不到（实测），新增 napi 导出 `log(msg)`，页面统一走它，落在 `dmhost` tag。

## 3. present 参数对齐（`ohos/gfx_vk_present_ohos.c::swap_make`）

按 `demo_ohos.c` 在同一设备上的实测结论改：

- surface 格式与色彩空间成对取（`fs[i].format` + 对应 `colorSpace`），不再固定 `SRGB_NONLINEAR`；
- extent 用 `dm_ohos_surface_size()`（OHOS 没有 ANativeWindow），先定 transform，再按（90°/270° 时交换过的）`min/maxImageExtent` 夹取；
- composite alpha 从 `supportedCompositeAlpha` 里选（本机只有 INHERIT 0x8）；
- transform 优先 IDENTITY；90°/270° 在夹取后交换宽高；
- `TRANSFER_DST` 改为硬性要求：每帧都要 clear + blit，surface 不支持就不能上屏，直接报错返回，不再"条件性加上却无条件使用"；
- present mode 取 FIFO（vsync 由合成器节流）；
- 失败路径补 `swap_destroy()`，`acquire` 返回的 image index 加 `>= g_ni` 越界保护，submit 失败用一次空提交把 fence 拉回可等待状态（否则下一帧永久等待）。

## 4. 表面生命周期与模块目录

- 每次 `onLoad` 都重报 surface（`reportSurface()`），`started` 只约束"释放数据 + 启动"；旋转/回前台后 XComponent 会换新 surface，旧代码在 `startOnce()` 里被 `started` 挡住 → 永久黑屏。
- 旧 `OHNativeWindow` 在 swapchain 销毁之后 `OH_NativeWindow_DestroyNativeWindow`（`dm_ohos_window_resized()` 持锁、`vkDeviceWaitIdle`，之后才释放）。
- `front_ohos.c` 补上 `<root>/env.txt` 解析（`KEY=VALUE`，与 Android 一致），路径类环境变量改为覆盖写；`dm_main` 的模块目录参数改为 `<root>/mods`——打包布局与 Android 一致（`mods/`、`RomFS/`、`env.txt`、`shaders.dmsv`），`Index.ets` 的游戏判定也改成 `mods/main.patched.bin` + `RomFS/`。

## 5. 重写器 ohos 目标（真实 NSO 回归）

输入：BOTW (`01007EF00011E000`) 的 ExeFS（`main` 23 MB、`sdk` 5.3 MB），`DM_TARGET=ohos`。

```
main {'window': 64, 'plain': 14639, 'pcrel': 271, 'cond': 269, 'br': 9, 'svc': 94, 'spin': 1335}
     cuts 0 obs 0 patch 902848 PATCH_OFF 0x2d70000 slot_refs 33362 gates 1429
sdk  slot_refs 22920 gates 103
```

产物 `*.fixups.tsv` 头部带 `# TARGET ohos` 与 `# KEY_TPOFF_IDX 4`。对补丁区反汇编，槽访问桩为：

```
mrs  x1, tpidr_el0
adrp x0, <key page>
ldr  x0, [x0, #0x20]      ; KEY_TPOFF（索引 4 × 8）
add  x1, x1, x0           ; tp + 槽块偏移
adrp x0, <key page>
ldr  x0, [x0]             ; KEY_K18（索引 0）
add  x1, x1, x0           ; 槽地址
ldr  x0, [x1]
```

与 `loader.c::install_key_page()` 的写入（`page[KEY_TPOFF] = tsd_off()`，其余为 `key_value(i) * 8`）一一对应；`thread.c::guest_thread_init()` 每个 guest 线程入口用 `dm_tsd_verify_thread()` 复核偏移，不一致直接 `die`（musl 的动态 TLS 偏移理论上可能随线程变化，宁可炸不可静默串号）。

`rtld` 在 apple/android/ohos 三目标下都在跳表分析处断言失败——它不是 profile 里的模块，属既有行为，不是本次回归项。

## 6. porter 的 HarmonyOS 流水线（`--platform hap`）

新增 `porter/platform_ohos.py`，CLI 加 `--platform {android,hap}` 与 `--dry-run`：


| 方案 | 实现 | 原因 |

### 数据包路径改为"相对"

### 数据包与应用侧契约的三处收口

1. **换包先清旧数据**：`Index.ets` 在 stamp 变化后先删 `mods/` `RomFS/` `aoc/` 再拷（对应 `datapack.OWNED`）。否则换版本后旧文件、或已被移除的 DLC 目录会留在设备上，而 `hle_misc.c` 是按 `DM_AOC_DIR` 下的数字子目录上报 DLC 持有数的。
2. **绝对路径进不了 OHOS 包**：`datapack.build(dev_root='')` 现在会检查 `env.txt` 的每一行，值以 `/` 开头就抛错——这种行在沙盒里必然指向不存在的路径，属于"装上去才发现"的故障。
3. **BC 纹理**：profile 的 `requires` 里有 `bcn` 时，Android 由 `install.py` 用设备能力挡；HAP 没有安装器，只在 `data` 节点打 `[RED]` 警告。Maleoon 是否支持 BC 尚未实测。

## 9. 第 6 轮审查（代码级，无真机可测）

3 个阻断项都是"上一轮已改但没改干净"：

| # | 问题 | 依据 | 改法 |
|---|---|---|---|
| 1 | 分块拷贝把 `ReadOptions.offset` 当绝对偏移 | d.ts 明写 "start position to read the data (it is determined by filePointer plus offset)"，而读会推进 filePointer → 第 2 MiB 起数据错位，但 `done == length`、stamp 照写 | 先 `fs.lseek(fd, rf.offset, SEEK_SET)`，此后只给 `length`（与两种语义都相容） |
| 2 | `present_window()` 持 `g_present_mu` 用 `UINT64_MAX` 等 acquire/fence | `dm_ohos_front_surface_lost()` 由 ArkTS 线程同步调用并要同一把锁 → 合成器不出图时 UI 线程卡死（demo 实测过该情形） | 两处改 100 ms 有界等待；拿不到图就丢这一帧（信号量未 signal、fence 未 reset，状态一致） |
| 3 | `fs.rmdir` 对非空目录抛 13900032 | d.ts 错误码表；异常被吞却仍写 stamp → 换包后旧数据残留且下次判 `ok` | 新增 `removeTree()` 自底向上删；失败向上抛 → `staging failed` + 不启动 |

风险与建议一并修：HAP 与 APK 不再共用 `<App>-data`（env.txt 一个是绝对路径、一个是裸名）；`startOnce()` 加 in-flight 标志（多 GB 首拷期间旋转会并发第二次 staging）；mkhap 拷包前按"两份包体积"检查构建盘余量；`versionCode` 改 epoch（原 `% 100000` 约 27.8 h 回绕，回绕后比上一版小会被拒装）；`--gfx null` 下 `dm_ohos_window_resized` 改弱符号；`env.txt` 绝对路径的 `BuildError` 归位（原来抛 `ValueError` 直接 traceback）；`env_under_root()` 的 `snprintf` 截断打 RED；surface 尺寸改 `getXComponentSurfaceRect()`（整屏 `display` 在分屏/自由窗口下不对，字段名是 `surfaceWidth/surfaceHeight`，写错时 hvigor 直接报错）；帧计数改扫本进程行。
